Add a `strip_strings` class Meta option that strips leading and trailing whitespace from string input on load, because form data often arrives as `"  ann@example.com "`.

## API

```python
class SignupSchema(Schema):
    email = fields.Email()
    name = fields.Str(validate=validate.Length(min=1))
    password = fields.Str(metadata={"strip": False})
    tags = fields.List(fields.Str())

    class Meta:
        strip_strings = True

SignupSchema().load({"email": " ann@example.com ", "name": " Ann ", "password": " pw ", "tags": [" a ", "b "]})
# {"email": "ann@example.com", "name": "Ann", "password": " pw ", "tags": ["a", "b"]}
SignupSchema().load({"name": "   "})   # ValidationError: {"name": ["Shorter than minimum length 1."]}
```

## Rules
- Store it in `SchemaOpts` as `strip_strings`, default `False`. A non-bool value raises `ValueError("`strip_strings` must be a boolean.")` when the schema class is defined.
- When `True`, every `String` field (including subclasses such as `Email` and `Url`) bound in that schema strips its input with `str.strip()` on load.
  - The strip happens before the field's own checks and before validators.
  - It also covers string fields nested inside container fields of that schema, such as `List(Str())`, `Tuple`, and `Dict(values=Str())`.
- A field with `metadata={"strip": False}` is never stripped.
- Fields of a `Nested` schema follow that nested schema's own option.
- Dump is not affected. Non-string input still raises the field's usual `invalid` error.

## Done when
- The option is read in `src/marshmallow/schema.py` and documented in the `Schema.Meta` docstring. The stripping itself may live in `fields.py`.
- Tests are added to `tests/test_options.py`.
