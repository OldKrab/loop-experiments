Add a `Duration` field to `marshmallow.fields` that (de)serializes `datetime.timedelta` as an ISO 8601 duration string. Unlike `TimeDelta`, which uses a number, this is for APIs that exchange strings like `"P1DT2H30M"`.

## API

```python
class Duration(Field[dt.timedelta]):
    default_error_messages = {
        "invalid": "Not a valid ISO 8601 duration.",
        "ambiguous": "Durations with years or months are not supported.",
    }

    def __init__(self, precision: str = "microseconds", **kwargs): ...
```

- `precision` must be `"seconds"` or `"microseconds"`. Anything else raises `ValueError("The precision must be one of: seconds, microseconds.")`. With `"seconds"`, microseconds are dropped (truncated toward zero) on both dump and load.
- Export it in `fields.__all__`.

## Serialization (timedelta -> str)
- Format: `[-]P[nD][T[nH][nM][n[.f]S]]`, built from the absolute value. A leading `-` is added for negative durations.
- `nD` is the whole days. Hours, minutes and seconds come from the remainder. Zero components are omitted, and `T` appears only if some time component is non-zero. Weeks are never emitted.
- Fractional seconds: microseconds as 6 digits with trailing zeros stripped (`PT0.5S`, `PT0.0015S`).
- A zero duration is `"PT0S"`. `None` dumps as `None`.

| timedelta | dumps as |
|---|---|
| `timedelta(days=1, hours=2, minutes=30)` | `"P1DT2H30M"` |
| `timedelta(seconds=0.5)` | `"PT0.5S"` |
| `timedelta(days=-3)` | `"-P3D"` |
| `timedelta(hours=-1, seconds=-30)` | `"-PT1H30S"` |
| `timedelta(days=2, microseconds=1500)` | `"P2DT0.0015S"` |
| `timedelta(hours=26)` | `"P1DT2H"` |
| `timedelta(0)` | `"PT0S"` |
| `timedelta(seconds=1, microseconds=999)` with `precision="seconds"` | `"PT1S"` |

## Deserialization (str -> timedelta)
- Accepts `[+|-]P[nW][nD][T[nH][nM][n[.f]S]]`, case-insensitive. Components are non-negative integers, except seconds, which may have a fraction with `.` or `,` as the separator.
- Fraction digits beyond 6 are truncated.
- At least one component is required, and a `T` must be followed by at least one time component.
- A `timedelta` instance is returned unchanged.
- Years (`nY`) or months (`nM` before `T`) raise the `ambiguous` error.
- Any other input raises `invalid`. That includes non-strings, empty strings, `"P"`, `"PT"`, `"P1DT"`, garbage, and values out of `timedelta` range.

| input | loads as |
|---|---|
| `"P1DT2H30M"` | `timedelta(days=1, hours=2, minutes=30)` |
| `"p1dt2h30m"` | same as above |
| `"PT0.5S"` / `"PT0,5S"` | `timedelta(seconds=0.5)` |
| `"-P3D"` | `timedelta(days=-3)` |
| `"+PT90M"` | `timedelta(minutes=90)` |
| `"P2W"` | `timedelta(days=14)` |
| `"PT1.1234567S"` | `timedelta(seconds=1, microseconds=123456)` |
| `"P1Y"`, `"P2M"`, `"P1Y2M3D"` | `ambiguous` error |
| `"PT2M"` | `timedelta(minutes=2)` (M after T is minutes) |
| `"P"`, `"PT"`, `"P1DT"`, `"1D"`, `""`, `12` | `invalid` error |
