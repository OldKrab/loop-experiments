Add a `key_case` class Meta option, so that schemas can expose snake_case attributes as camelCase or kebab-case keys without setting `data_key` on every field.

## API

```python
class UserSchema(Schema):
    user_id = fields.Int()
    display_name = fields.Str()
    html_url = fields.Str(data_key="link")

    class Meta:
        key_case = "camel"   # or "kebab"; default None (keys = attribute names)

UserSchema().dump({"user_id": 1, "display_name": "Ann", "html_url": "u"})
# {"userId": 1, "displayName": "Ann", "link": "u"}
UserSchema().load({"userId": 1, "displayName": "Ann", "link": "u"})
# {"user_id": 1, "display_name": "Ann", "html_url": "u"}
```

## Rules
- Store it in `SchemaOpts` as `key_case`, default `None`. Any other value than `None`, `"camel"` or `"kebab"` raises `ValueError("`key_case` must be one of: camel, kebab.")` when the schema class is defined.
- Conversion of a field name: split on `_` and drop empty parts.
  - `camel`: keep the first part as is, and upper-case only the first character of each later part.
  - `kebab`: join the parts with `-`.

  | field name | camel | kebab |
  |---|---|---|
  | `user_id` | `userId` | `user-id` |
  | `html_url` | `htmlUrl` | `html-url` |
  | `_private_note` | `privateNote` | `private-note` |
  | `api_URL` | `apiURL` | `api-URL` |
  | `name` | `name` | `name` |
  | `x2_value` | `x2Value` | `x2-value` |
- An explicit `data_key` on a field always wins.
- The converted key is used everywhere a data key is used:
  - dump output and load input;
  - error message keys (`ValidationError.messages` is keyed `{"userId": [...]}`);
  - unknown-field handling (`"user_id"` in the input is unknown for a camel schema and raises with the default `unknown=RAISE`);
  - `validates("user_id")` decorators keep using the attribute name, as for `data_key`.
- `only`, `exclude`, `load_only`, `dump_only` and `partial` keep using attribute names.
- Nested schemas use their own `Meta.key_case`. A parent's option does not apply to the fields of a `Nested` schema, although the nested field's own key in the parent is converted.
- A subclass inherits `key_case` exactly as other Meta options are inherited.
- If two fields convert to the same key (e.g. `user_id` and `userId` in one camel schema), instantiating the schema raises the existing data_key collision `ValueError`.

## Done when
- The option lives in `src/marshmallow/schema.py` and is documented in the `Schema.Meta` docstring, next to the other options.
- Tests are added to `tests/test_options.py`.
